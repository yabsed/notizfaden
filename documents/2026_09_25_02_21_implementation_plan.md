# Keep에 가까운 소셜 메모 앱 구현 제안

상태: 구현 전 제안. 2026-09-25 로컬 참고 코드를 조사해 작성했다.

## 제품 원칙

- 첫 화면은 항상 내 메모다. 제목 없이 입력하고 자동 저장한다.
- 새 메모와 다른 사람의 메모에서 파생한 메모는 항상 비공개로 시작한다.
- 별도 게시물을 만들지 않고 메모의 공개 범위를 바꾼다.
- 공개 메모의 이후 수정도 공유된다. 편집 화면에서 현재 공개 범위를 계속 보여준다.
- 둘러보기는 별도 메뉴다. 좋아요 수, 조회 수, 팔로워 수와 인기 순위는 초기 범위에서 제외한다.

## 기술 구성

초기 추천은 React + TypeScript + Vite로 반응형 UI를 만들고, 같은 빌드 결과를 웹과 Capacitor Android 앱에서 사용하는 것이다. Go API와 PostgreSQL을 공통 서버로 둔다. 첨부파일은 S3 호환 저장소에 저장한다.

Capacitor는 웹 UI를 Android WebView 안에서 실행하고 네이티브 API와 연결하는 런타임이다. Kotlin 네이티브 UI와 동일한 것은 아니다. 개발 초기에 실제 Android 기기로 한글 조합 입력, 키보드와 편집 화면, 뒤로 가기, 긴 메모 및 카드 스크롤을 검증한다. 위젯과 다른 앱에서 텍스트 받기는 별도 네이티브 구현 범위다. 네이티브 입력 감각과 위젯이 출시 필수 조건이면 Kotlin/Compose Android + React 웹으로 나누는 편이 적합할 수 있다.

웹 로컬 저장소는 IndexedDB/Dexie를 사용한다. 초기 Android도 같은 저장 계층을 검증하되 저장소 인터페이스를 분리해 네이티브 SQLite로 교체할 수 있게 한다. Dexie 자체가 서버 동기화를 해결해 주지는 않는다. React의 서버 응답 캐시와 미전송 메모 저장소는 별개로 취급한다.

서버는 우선 단일 Go 서비스로 시작한다. 브라우저와 Android의 로그인 세션 유지 방식, 허용 origin, CSRF 방어 및 토큰 보관은 각각 검증한다. Private는 사용자 간 접근 제한을 뜻하며 종단 간 암호화를 약속하는 표현으로 사용하지 않는다.

예정 구조:

```text
app/
  client/              # React UI, 메모 모델, 로컬 저장, 동기화
    android/           # Capacitor Android 프로젝트
  server/              # Go API, 권한 검사, 데이터베이스 migration
documents/
submodules/            # 참고 코드
```

두 코드베이스 전체를 합치는 대신 참고할 부분을 선택한다. Memos 서버 포크는 기본 공개 메모 서비스를 빨리 검증하는 대안이지만, 이 제품의 체크리스트·색상·친구 관계·동기화 규약에는 별도 확장이 필요하다. 코드를 실제로 옮길 때는 원본 라이선스와 고지를 함께 유지한다.

## Keep에 가까운 화면

PC: 상단 검색, 왼쪽 메모/라벨/보관함/휴지통 메뉴, 중앙 간단한 입력창, 고정 메모와 나머지 메모, 높이가 다른 카드의 다열 배치. 리스트 전환도 제공한다.

Android: 상단 검색, 기본 2열 카드와 1열 전환, 빠른 텍스트·체크리스트 입력, 전체 화면 편집. 좁은 화면이나 큰 글꼴 설정에서는 1열로 조정한다. 마우스 hover 없이 모든 기능에 접근할 수 있어야 한다.

디자인의 기준은 얇은 테두리, 작은 모서리 곡률, 차분한 카드 색상, 조밀하지만 답답하지 않은 간격이다. 일반적인 SNS의 대형 프로필 헤더와 반응 버튼 줄을 내 메모 카드에 넣지 않는다. 독립적인 앱 이름과 아이콘을 사용한다.

공유 기능은 카드의 작은 공개 범위 표시와 편집 화면의 `나만 보기 · 친구 · 전체 공개` 선택기로 넣는다. 둘러보기에서도 동일한 카드 컴포넌트를 쓰되 작성자와 ‘내 메모로 이어 쓰기’만 추가한다. Friends를 구현하기 전에는 선택기를 활성화하지 않는다.

위 수치는 로컬 clone의 디자인 출발점이며 현재 Google Keep과 픽셀 단위로 같다는 뜻은 아니다. 시각 검증은 360/412px 모바일, 1280/1440px PC, 라이트/다크 모드, 긴 한글과 체크리스트를 대상으로 한다.

## 데이터와 공개 규칙

최소 엔티티는 users, notes, checklist_items, labels, note_labels, attachments, friendships, note_links, sync_changes, processed_mutations다.

- notes: 클라이언트 생성 UUID, 작성자, 선택적 제목, 본문, 종류, 색상, 고정/보관 상태, 공개 범위, revision, 생성/수정/공개 시각, 삭제 시각.
- checklist_items: 안정적인 항목 ID, 순서, 텍스트, 완료 여부. 편집 때마다 전체 텍스트로 재해석하지 않는다.
- friendships: 요청자, 수신자, 대기/수락 상태. 친구는 상호 수락 관계이며 일방적 팔로우와 구분한다.
- note_links: 파생 메모와 원본의 관계. 링크만으로 원본 열람 권한이 생기지 않는다.
- sync_changes: 서버가 발급하는 순서 커서와 변경/삭제 기록. 클라이언트 시계로 변경 순서를 판단하지 않는다.

읽기 권한은 작성자, 수락된 친구, 공개 범위를 서버에서 검사한다. 쓰기는 작성자만 가능하다. 단건 조회뿐 아니라 목록, 검색, 첨부파일, 관계, 동기화 응답 모두 같은 권한 규칙을 적용한다.

처음에는 Private/Public을 구현하고 Friends는 관계 모델과 권한 테스트가 갖춰진 다음 추가한다. 피드는 최신 공개 시각 기준으로 시작하며 내용 수정만으로 상단에 다시 올리지 않는다. 노트 보관은 개인 정리 상태로 취급하고 공개 취소와 구분한다. 삭제는 공개 접근도 중단한다.

전체 공개 메모의 이어 쓰기는 복사본을 내 비공개 메모로 만들고 출처를 연결한다. 원본이 비공개로 전환되면 원본 미리보기를 숨긴다. 이미 저장된 복사본까지 회수할 수 있다고 약속하지 않는다. 친구 메모의 재공유 정책이 정해지기 전에는 해당 이어 쓰기를 제외한다.

## 저장과 동기화

1. 입력을 로컬 DB에 저장하고 전송 대기 작업도 같은 트랜잭션에 기록한다. 서버 응답을 기다려 입력을 막지 않는다.
2. 각 작업에 mutation ID와 base revision을 붙인다. 서버는 중복 요청을 한 번만 적용한다.
3. 서버는 권한을 확인한 뒤 revision이 일치할 때만 변경한다. 변경 기록도 같은 트랜잭션에서 남긴다.
4. 충돌 시 두 버전을 보존하고 사용자가 선택하도록 한다. 조용히 마지막 내용으로 덮어쓰지 않는다. 초기에는 CRDT를 도입하지 않는다.
5. 로그인/앱 재진입/연결 복구 때 커서 이후 변경을 가져온다. 앱이 켜져 있을 때 SSE를 추가할 수 있지만, 누락 복구는 항상 커서 기반 API로 한다.
6. 삭제 tombstone을 전파해 오프라인 기기가 삭제 메모를 되살리지 않도록 한다. 오래된 커서는 전체 재동기화가 필요하다.

공개 범위 변경은 본문 자동 저장과 분리하고 서버 승인을 받은 뒤 완료로 표시한다. 오프라인에는 공개 변경을 보류하며 비공개 전환이 아직 서버에 적용되지 않았음을 표시한다. 오래된 본문 저장 작업이 공개 범위를 덮어쓸 수 없게 한다.

다른 사람의 메모는 초기에는 온라인 열람으로 제한해 영구 오프라인 복사를 최소화한다. 권한 철회는 서버 요청부터 즉시 적용하고 활성 클라이언트의 피드/미리보기 캐시를 무효화한다. 이미 전달된 내용의 회수는 보장할 수 없다. 로그아웃과 계정 전환 때 개인 로컬 DB를 격리/정리하고, 미전송 작업은 삭제 전 명확하게 처리한다.

## 구현 순서와 완료 기준

1. **Keep UI와 로컬 메모:** 텍스트, 체크리스트, 자동 저장, 색상, 고정, 검색, 라벨, 보관/휴지통. React 화면을 초기에 Android에도 설치해 입력과 스크롤을 확인한다. 새로고침·재실행·오프라인 뒤에도 메모가 남아야 한다.
2. **계정과 두 기기 동기화:** 로그인, 서버 DB, outbox, revision, 삭제 동기화. 웹과 Android에서 같은 메모를 보고, 동시 편집 충돌에도 두 내용이 보존되어야 한다. 연결 재시도에도 중복 생성하지 않아야 한다.
3. **선택적 공개:** Private/Public, 공개 메모 상세 링크, 둘러보기. 다른 사용자가 비공개 메모·첨부·검색 결과를 얻지 못하며 공개 취소가 서버에 즉시 적용되어야 한다.
4. **생각의 연결:** 친구 요청/수락, Friends 공개, 공개 메모 이어 쓰기, 출처 연결. 친구 해제 후 접근이 차단되고 파생 메모가 기본 비공개여야 한다. 공개 서비스 운영 전에는 차단/신고와 대응 도구도 갖춘다.
5. **Android 사용성 확대:** 다른 앱에서 공유받기, 알림, 위젯은 우선순위에 따라 추가한다. 대용량 카드 목록과 첨부파일 업로드를 실제 기기에서 검증한다.

첫 결과물은 1단계다. 디자인을 평가할 수 있는 실제 메모 앱을 먼저 만든 뒤, 검증된 입력·저장 경험에 동기화와 공유를 더한다.
